# ChoreHero v1 — Accessibility Contract

> WCAG 2.1 AA is the floor. This document enumerates how the design
> package meets it, calls out the patterns every component and screen
> spec must obey, and lists the keyboard interactions a UAT engineer
> must verify.

## Conformance target

- WCAG 2.1 Level AA across every parent and kid surface.
- AAA target size (WCAG 2.5.5, 44×44 CSS px) on parent SPA.
- Larger custom minimums on kid SPA (56×56 interactive, 64×64
  primary CTA).
- `prefers-reduced-motion: reduce` honored across the app.
- Forced-colors / Windows High Contrast: brand-only signals always
  paired with a non-color signal (text or icon); shadows are
  decorative, never the sole cue.

## Color & contrast

All text/background pairs in the design pass WCAG AA for their
intended use. The audited pairs live in `tokens/tokens.json` under
`color.paired_contrast`. Excerpt:

- Body text on `--ch-color-neutral-paper-050` and `--ch-surface-card`
  must use `--ch-text-primary` (ink_900) or `--ch-text-secondary`
  (ink_700). `--ch-text-tertiary` (ink_500) on paper_050 measures
  4.6:1 and is permitted only for helper / metadata copy, not body
  paragraph text.
- Disabled text uses `--ch-text-disabled` (ink_300) and is exempt
  from contrast (per WCAG 1.4.3).
- Success pair (`paper_000 on success_600`) is 3.8:1 — large-text
  only. Therefore success buttons use ink_900 text on the same
  success_600 background (5.6:1).
- Sunshine (yellow) is permitted only with ink_900 text. White on
  yellow fails (1.4:1) and is forbidden.

## Focus

- `:focus-visible` only. Mouse focus never shows the ring.
- Focus ring is `--ch-focus-ring-shadow` (3px violet ring + 2px
  white inner offset).
- A control's focus ring must be visible against the surface it sits
  on (the inner offset is the surface color so the ring is visible
  on any background).
- Focus order follows DOM order. Visual order must match DOM order.
- When opening a modal, focus moves to the modal container; on close,
  focus returns to the trigger.
- When opening a toast, focus does not move. When opening a
  celebration modal, focus moves to the modal container.

## Keyboard

Every interactive element must be reachable and operable by keyboard.
The contract:

| Element              | Keys                                  |
|----------------------|----------------------------------------|
| Button               | `Enter` / `Space` activate.            |
| Link                 | `Enter` activates.                     |
| Text input           | Focus traps inside; `Tab`/`Shift+Tab` cycle. |
| Select (native)      | `Space`/`Enter` open; arrow keys cycle options; `Esc` close. |
| Custom select        | `Enter`/`Space` open; arrow keys cycle + select; `Esc` close. |
| Modal                | `Esc` close; focus trapped while open. |
| Toast                | `Tab` does not reach; explicit `Dismiss` button only on parent SPA. |
| Bottom nav (kid)     | Arrow keys cycle left/right; `Enter` activates. |
| Top nav (parent)     | `Tab` cycles; `Enter` activates; `Home`/`End` jump to first/last. |
| Tab list             | Arrow keys cycle tabs; the active tab `Enter`s. |
| Table row            | `Enter` opens detail (parent SPA); rows are not buttons themselves. |
| Streak milestone card | `Enter`/`Space` dismiss; `Esc` dismisses. |

### Skip link

Every parent SPA page has a "Skip to main content" link as the first
focusable element. Kid SPA does not (single-screen kiosk).

## ARIA patterns

- Landmarks: `<header>`, `<nav>`, `<main>`, `<aside>`, `<footer>`
  on both SPAs. Kid SPA's `<nav>` is the bottom bar.
- Headings: one `<h1>` per screen, descending by level.
- Live regions: toasts use `role="status"` (polite) for
  success/info/celebrate, `role="alert"` (assertive) for
  warning/danger. Notification lists use `aria-live="polite"`
  with `role="log"`.
- Form fields: every input has a `<label>` (visible). Placeholder
  is not a substitute. Required fields use `aria-required="true"`
  and visual `*`.
- Errors: each input with an error gets `aria-invalid="true"` and
  `aria-describedby` pointing to the error text.
- Dialogs: `role="dialog"`, `aria-modal="true"`, labelled by the
  dialog title; focus trapped.
- Decorative imagery: `alt=""` + `role="presentation"`.
- Identical-name elements must each carry a unique `aria-label` (e.g.
  multiple "Done" buttons in a chore list need an `aria-label="Mark
  [chore name] done"`).

## Touch targets

- Parent SPA: ≥ 44×44 CSS px on every interactive element.
- Kid SPA: ≥ 56×56 on every interactive element; ≥ 64×64 on primary
  CTAs (`Done`, `Claim`, `Send request to a grown-up`).
- Spacing between adjacent targets: ≥ 8 CSS px.
- A target smaller than the minimum is allowed visually (a thin
  chip) but pads its bounding box to reach the minimum. UAT verifies
  via inspector.

## Motion

- `prefers-reduced-motion: reduce` clamps durations to 0ms and
  easings to linear in `tokens/tokens.css`. Components must not
  override.
- Pulse, celebratory scale, streak shimmer, progress-ring spin:
  all disabled under reduced-motion. Static colour/state still
  provides the cue.

## Forced colors

- Shadows are decorative; in forced-colors mode, the design
  collapses shadows and relies on borders + colours set per
  component.
- Components must also apply `@media (forced-colors: active)`
  overrides when brand colour is the only signal (e.g. focus ring
  must use `Highlight` system colour, not the brand violet).

## Forms

- Submit order: visual order = DOM order = tab order.
- Errors below their fields (`aria-describedby` from field to
  error message), red colour paired with an icon and text.
- "Required" indicator is a visible `*` next to the label +
  `aria-required="true"`.
- "Optional" labels are forbidden; every field has a clear required
  state.
- Password inputs have a `Show password` toggle with proper
  `aria-pressed`.

## Tables (parent SPA)

- Tables use `<table>` with proper `<thead>`, `<tbody>`, `<th
  scope="col">`.
- Sortable columns announce `aria-sort` on the `<th>`.
- Row actions live in the last column and are buttons with
  `aria-label="Open [item]"` (not "Edit", to avoid collision in
  the same column).

## Modal pattern

- Focus traps inside the dialog. Tab cycles within. Shift+Tab cycles
  backwards.
- `Esc` closes. The close `×` button has `aria-label="Close"`.
- Background is `aria-hidden="true"` while modal is open.
- After close, focus returns to the trigger element.

## Reduced data / zoom

- Layouts must remain usable at 200% browser zoom.
- Layouts must remain usable at 320 CSS px width (small phone).
- Text remains sharp at 200% — no sub-pixel font sizes; minimum
  11px.

## Tables of testable patterns

These are the patterns UAT uses to score a component:

| Pattern                       | Pass criteria                          |
|-------------------------------|----------------------------------------|
| Keyboard reachable            | Tab reaches it; Enter/Space activates. |
| Visible focus                 | Focus ring renders on `:focus-visible`. |
| Correct ARIA role             | Matches the documented pattern.        |
| Accessible name               | `aria-label` or visible text identifies the element. |
| Hit target                    | Bounds match the surface min.          |
| Color contrast                | Pair is in the audited contrast list.  |
| Forced-colors                 | Component remains usable.              |
| Reduced-motion                | Component remains understandable with motion off. |

## Anti-patterns (rework triggers)

- ❌ A clickable `<div>` instead of a real `<button>` / `<a>`.
- ❌ A `disabled` attribute when `aria-disabled` is what the design
     uses.
- ❌ An `aria-label` that restates the visible text.
- ❌ A modal that doesn't trap focus.
- ❌ A toast that steals focus.
- ❌ A focus ring that relies on `:focus` (works only on click).
- ❌ A success message conveyed by colour alone.
- ❌ A parent SPA touch target smaller than 44dp.
- ❌ A kid SPA primary CTA smaller than 64dp.
